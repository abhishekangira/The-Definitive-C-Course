# CLAUDE.md: The Definitive C Course

This is an interactive, static (no backend) React + TypeScript web app that teaches C17 and low-level fundamentals to front-end engineers. **Read `PLAN.md` first.** It is the source of truth for architecture, the content format (§2.4), the verification pipeline (§3), the course outline (§6) and the per-module definition of done (§3.6).

## Non-negotiables (client spec)
- **The learner is never passive.** At most ~250 words or one animation/video before an interaction.
- **Every `id` code fence is predict-before-run.** Run without a prediction is allowed only inside CT/FB editors. Every C fence in prose has `id=` or `fragment`.
- **Every expected output and prediction answer is generated by running code** (`tools/verify`), never typed by hand.
- **UB appears in a prediction only when UB is the lesson.** The question is then categorical (crash? same value every run? what does UBSan/ASan/the compiler report?). The answer is the set of outcomes observed across targets and 3 runs. Garbage values are never asked.
- **Samples compile cleanly with `-std=c17 -Wall -Wextra -pedantic`** in gcc 13, clang 22 *and* the browser compiler, and run ASan+UBSan-clean natively, unless the lesson deliberately shows an error.
- **Native (x86-64) vs browser (wasm32) output differences are flagged automatically.** A flagged sample needs `platform` plus `predict64=…` or `predict64=none reason=…`. It shows the browser result and the learner's platform result.
- **Reference solutions pass; starters fail** (variants too). Every lesson is clicked through with Playwright.
- **Progress lives in `localStorage`** under `tdcc:v1:*` keys, with export and import as a file.
- **Content lives in `content/`** (MDX/YAML), separate from `src/`.
- **Outside resources:** at most 1–2 per module, each naming an exact chapter or lecture.
- **YouTube:** at most 2 segments per module, only when they clearly beat the app. Each goes in `videos.json` with `why`.

## Conventions
- **C standard and POSIX.**
  - C17 + the standard library.
  - POSIX only in M11 (`dlopen`), M13 and the capstone's provided `memlib`.
  - POSIX samples start with `#define _POSIX_C_SOURCE 200809L`. Add `_DEFAULT_SOURCE` (glibc `d_type`) or `_DARWIN_C_SOURCE` (macOS `MAP_ANON`) where needed, and mark the fence `posix`.
- **`learnc.h`** is the course helper (MIT, our own). Don't ship libcs50 (its licensing is ambiguous). No libc `rand()` in prediction answers; use the `learnc.h` PRNG.
- **Normalisation.** Only `%p` output is normalised to `<addrN>`. On those lines `0`, `0x0` and `(nil)` mean NULL.
- **Traces** come from x86-64 Linux gdb and are labelled as such. Size and address questions are platform-tagged; addresses are derived (base + offset).
- **Analogies** use `<Analogy js c breaksDown>`, and the breakdown must be real.
- **Routing.** HashRouter with Vite `base: './'`. The toolchain URL is resolved on the main thread and passed to the workers.

## Key technical decisions (details in PLAN.md §1–§4)
- **In-browser compiler:** `@yowasp/clang@22.0.0-git20542-10` (pinned). Programs run with `@bjorn3/browser_wasi_shim@0.4.2` in a per-run worker.
- **Browser flags:**
  ```
  -std=c17 -Wall -Wextra -pedantic -O0 -g -fno-color-diagnostics -D_WASI_EMULATED_PROCESS_CLOCKS -D_WASI_EMULATED_SIGNAL
  -lc-printscan-long-double -lwasi-emulated-process-clocks -lwasi-emulated-signal
  -Wl,-z,stack-size=1048576 -Wl,--max-memory=268435456
  ```
  - Always link `course_rt.c`, which flushes stdout before stdin reads.
  - Guardrail mode adds `-fsanitize=undefined -fno-sanitize-recover=all` plus `ubsan_rt.c`, which must implement *all* handlers.
  - Leak checks use `leakcheck.c` with `-Wl,--wrap=malloc,--wrap=free,--wrap=calloc,--wrap=realloc`. Never use `-include` macros: they break when memory is freed in a different translation unit, or when `free` is passed as a pointer.
  - Always run under `WebAssembly.promising` when JSPI exists.
- **Gotchas found in research:**
  - Prefetch with `runClang(null, {}, {fetchProgress})`.
  - Pass `{debug:false}` to `new WASI(...)`.
  - Pass `decodeASCII:false`.
  - Patch `fetch` before importing the yowasp bundle.
  - Never `await cache.put()` in the fetch hook.
  - Override `poll_oneoff` (`sleep` busy-waits).
- **Native CI toolchain:** Ubuntu 24.04 with gcc 13, clang 22 (apt.llvm.org) + `libclang-rt-22-dev`, gdb 15, valgrind 3.22, Node ≥22, FFmpeg and a pinned Chromium. Per-target runners: macOS arm64 (all samples), ubuntu-24.04-arm and windows-latest (`platform` samples).
- **Local project runner:** `check.mjs` (zero dependencies, Node 18+) via `make test`. It reads `.learner` (the seed) and prints progress codes and completion tokens via the shared `tools/check/token.mjs`.
- **Unit-test harness:** `#define main learner_main` plus `#include` of the file defining `main`, with `-Wreturn-type` silenced. Never trust its return value. Multi-file projects are tested through `make` targets in `check.json`.

## Environment recipes (verified in this cloud container)
- **YouTube.**
  - Check a video exists:
    ```
    curl "https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<ID>&format=json"
    ```
  - Download a transcript:
    ```
    yt-dlp --js-runtimes node --extractor-args "youtube:player_client=web_embedded" --ignore-no-formats-error --skip-download --write-subs --write-auto-subs --sub-langs "en" --sub-format vtt -o "%(id)s" "https://www.youtube.com/watch?v=<ID>"
    ```
  - Default clients hit a bot check, and bursts get 429 errors, so fetch slowly.
  - Commit transcript excerpts; CI must not call yt-dlp.
- **HyperFrames.**
  - Prerequisites: Node ≥22 and FFmpeg.
  - Environment: `HYPERFRAMES_NO_TELEMETRY=1 HYPERFRAMES_SKIP_SKILLS=1 HYPERFRAMES_NO_UPDATE_CHECK=1 HYPERFRAMES_BROWSER_PATH=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`.
  - Read `.agents/skills/hyperframes-core` (plus `-animation`, `-registry`, `general-video`, `media-use`) before authoring.
  - The rules are in PLAN.md §4.6. Commit only the MP4s; WebM is transcoded at deploy.
  - Skip the skills' interactive and online steps (intent interview, `usage`, `publish`, `auth`, `skills update`).
- **Chromium** is at `/opt/pw-browsers`. Don't run `playwright install`. Open-source Chromium can't play H.264, so e2e tests use a WebM fixture.
- **GitHub.** Web and API access is limited to repos attached to the session. `gh repo create` and GraphQL are blocked; use repo-scoped REST.
