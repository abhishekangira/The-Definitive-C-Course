# CLAUDE.md: The Definitive C Course

This is an interactive, static (no backend) React + TypeScript web app that teaches C17 and low-level fundamentals to front-end engineers. **Read `PLAN.md` first.** It is the source of truth for architecture, the course outline and the per-module definition of done.

## Status
- Stage 1 (research + PLAN.md) is done and awaiting review.
- Stage 2 (app shell + Module 1) has not started. There is no app code yet.
- The client reviews after each stage and each module. Stop and ask for review at those points.

## Non-negotiables, from the client spec
- **The learner is never passive.** At most about 250 words of prose, or one animation or video clip, before an interaction. Code examples are predict-before-run.
- Every expected output and prediction answer is generated by running code (`tools/verify`), never typed by hand. UB is never a prediction answer unless UB is the lesson.
- Every sample compiles with `-std=c17 -Wall -Wextra -pedantic` (+ASan where relevant) unless it deliberately shows an error.
- Samples whose native (x86-64) and browser (wasm32) outputs differ are flagged automatically. They show both outputs, plus the 64-bit prediction step where it is derivable.
- Reference solutions pass their tests; starters fail them. Every lesson is clicked through with Playwright.
- Progress lives in `localStorage`, with export and import as a file. Course content lives in `content/` (MDX/YAML), separate from `src/`.
- At most 1–2 outside resources per module, each naming an exact chapter or lecture. At most 2 YouTube segments per module, all listed in `videos.json`.

## Key technical decisions (details in PLAN.md §0–§4)
- **In-browser compiler:** `@yowasp/clang@22.0.0-git20542-10` (pinned exactly). Programs run with `@bjorn3/browser_wasi_shim@0.4.2` in a per-run worker.
- **Browser flags:**
  ```
  -std=c17 -Wall -Wextra -pedantic -O0 -g -D_WASI_EMULATED_PROCESS_CLOCKS -D_WASI_EMULATED_SIGNAL
  -lc-printscan-long-double -lwasi-emulated-process-clocks -lwasi-emulated-signal
  -Wl,-z,stack-size=8388608 -Wl,--max-memory=268435456
  ```
  Always link `course_rt.c` (it flushes stdout before stdin reads).
- **Gotchas found in research:**
  - Prefetch with `runClang(null, {}, {fetchProgress})`.
  - Pass `{debug:false}` to `new WASI(...)`.
  - Pass `decodeASCII:false`.
  - Patch `fetch` before importing the yowasp bundle.
  - Never `await cache.put()` inside the fetch hook.
- **Native CI toolchain:** gcc 13 + clang 18 on Ubuntu 24.04. clang sanitizers need `libclang-rt-18-dev` (the container's clang lacks compiler-rt; gcc's ASan works).
- **Local project runner:** `check.mjs`, zero dependencies, Node 18+, invoked by `make test`.
- **Stepper traces:** gdb-Python tracer + malloc/free `--wrap` shim (`tools/trace`).

## Environment recipes (verified in this cloud container)
- **YouTube:**
  - Check a video exists: `curl "https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<ID>&format=json"`.
  - Transcript:
    ```
    yt-dlp --js-runtimes node --extractor-args "youtube:player_client=web_embedded" --ignore-no-formats-error --skip-download --write-subs --write-auto-subs --sub-langs "en" --sub-format vtt -o "%(id)s" "https://www.youtube.com/watch?v=<ID>"
    ```
    Default clients hit a bot check from this IP. Fetch transcripts slowly; YouTube returns 429 on bursts.
- **HyperFrames:**
  - Set `HYPERFRAMES_NO_TELEMETRY=1 HYPERFRAMES_SKIP_SKILLS=1 HYPERFRAMES_NO_UPDATE_CHECK=1 HYPERFRAMES_BROWSER_PATH=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`.
  - Read `.agents/skills/hyperframes-core` before authoring. Authoring rules are in PLAN.md §4.6.
  - Skip the skills' interactive and online steps (intent interview, `usage`, `publish`, `auth`, `skills update`).
- **Chromium:** at `/opt/pw-browsers`. Do not run `playwright install`. Open-source Chromium can't play H.264, so test with WebM.
- **GitHub:** web/API access is limited to repos attached to the session. `gh repo create` and GraphQL are blocked; use repo-scoped REST.
