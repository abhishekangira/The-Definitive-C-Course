# e2e/: the Playwright click-through and axe checks

`npm run e2e` tests the production build, so run `npm run build` first. `lib.ts` completes every interaction from the generated data.

## Running
- **Browser.** In the cloud container Chromium is at `/opt/pw-browsers`; don't run `playwright install` there. Elsewhere run `npx playwright install chromium` first: `playwright.config.ts` falls back to Playwright's own Chromium, and `CHROMIUM_PATH` selects another.
- **Workers.** CI runs 2 workers and local runs 3 (`playwright.config.ts`). `fullyParallel` stays false because `test.describe.serial` groups share one page. The benchmarks behind both numbers are in `docs/adr/0002-e2e-workers.md`; bench again before changing them.
- **`npm run e2e:stress [-- <playwright args>]`** runs the full suite with `--repeat-each=$E2E_STRESS_REPEAT` (default 5) while `$E2E_STRESS_LOAD` busy-loop processes (default: one per usable CPU) run, with `--retries=0`. Select whole spec files, not `-g` (the lesson tests are a serial group). It passes no `--workers`, so it uses the config's count. `E2E_DELIBERATE_FAIL=1 npx playwright test failure-artifacts` shows the failure artifacts.
- **A leftover `vite preview` on port 4173 serves another checkout's `dist/`** (`reuseExistingServer` is on outside CI) and an unbuilt worktree hangs for 60 s with "Timed out waiting from config.webServer". Build first and give each worktree its own `E2E_PORT`.
- **Never `pkill -f` a pattern that is also in your own command line.** `pkill -f "vite preview" && …` in one Bash call kills that shell (exit 144) and the rest of the line never runs. Start the preview server in its own call (`nohup npx vite preview --port 4173 --strictPort &`) and stop it by PID.

## Pitfalls
- Test harness: `AxeBuilder` needs pages from `browser.newContext()`; scope `summary` locators with `:scope >` because exercises contain nested `<details>`.
- **Playwright `getByText` with a regex does not trim.** An icon before the words leaves a leading space, so `/^Right\./` misses and `/^\s*Right\./` matches; a plain string (with `exact: true`) is trimmed. Check the button name too: an `aria-hidden` icon adds nothing to it, so `name: 'Step', exact: true`.
- **Wait for a signal that identifies the page.** A bare `h1` also matches the page you are leaving; use the specific heading text or a `data-*` attribute.
- **Failure artifacts for own contexts.** With `trace: 'retain-on-failure'` and `screenshot: 'only-on-failure'`, Playwright 1.56.1 attaches a trace and a screenshot to a failing test even when its page comes from `browser.newContext()`, in the test body or in `beforeAll` (observed with `E2E_DELIBERATE_FAIL=1 npx playwright test failure-artifacts`). Don't add a tracing helper; starting `context.tracing` yourself fails with "Tracing has been already started".
- **`e2e:stress` is not proof of stability.** With #25's per-card wait deleted, `course.spec.ts` still passed under 3x CPU load (load average 27, 4 repeats) and with Chromium CPU-throttled 6x and 30x (CDP `Emulation.setCPUThrottlingRate`, 1 run each). A pass is weak evidence: fix races by reading the wait, not by stress alone.
- **Reproduce an e2e timing flake under load, and bound its hang (#58).** On an idle machine the reduced-motion and keyboard animation tests each passed 30 of 30; under `E2E_STRESS_LOAD=6 npm run e2e:stress -- e2e/animation.spec.ts --grep "reduced motion" --workers=2 --repeat-each=30 --timeout=60000` it failed 3 of 30, always at the one-shot `naturalWidth` read (an unloaded `<img>` already has a layout box, so `toBeVisible` passes first). Wait with `expect.poll` on `complete`, `naturalWidth` and `currentSrc`. `playwright.config.ts` has no `actionTimeout`, so a `click()` on an element that never appears waits for the whole 10 minute test timeout; tests that take seconds set `test.setTimeout(60_000)`. To see inside a worker, add temporary `console.log` calls and listen with `page.on('console')` (worker logs arrive there in Playwright 1.56.1) next to a scratch spec that samples the page every 100 ms; delete both before committing. The keyboard-playback flake of the same issue did not reproduce in 160 runs (30 idle, 30 under load, 100 at the CI worker count), so its cause is not established.
- **Testing offline.** The app is not an offline app (the page itself needs the network), so `context.setOffline(true)` followed by a reload fails with `ERR_INTERNET_DISCONNECTED`. To test "works without the network", abort only the toolchain URLs with `context.route`. `context.route` sees worker requests, `context.on('request')` logs them, and CDP `Network.emulateNetworkConditions` on the page throttles the compiler worker too. Probe the request log in the same test where requests must appear, or `expect(requests).toEqual([])` proves nothing.
- **Seeding a bad cache entry in a test:** keep the real entry's headers (`new Response(bytes, { headers: old.headers })`), or WebAssembly rejects it for its MIME type, not its bytes. Press Run while the failing load is still pending (hold the worker script with `context.route`), because a Run pressed after the page's own background load failed just starts a fresh load, which heals silently. How the cache treats each failure is in `src/runtime/AGENTS.md`.
- **Overflow checks under `isMobile: true` compare `scrollWidth` with `documentElement.clientWidth`, never `window.innerWidth`.** In mobile emulation Chromium grows `innerWidth` to the content width, so `scrollWidth <= innerWidth` always passes (a 600 px element gave 600/600/390). `e2e/phone-keyboard.spec.ts` found `#/settings` at 441 px that way (the `PlatformPicker` label and select did not wrap). Prove a layout test can fail by running it on the unfixed build. Also: a visually hidden radio (`.visually-hidden`) shows focus only through its label, so test the label, and `e2e` tests that depend on earlier serial tests should set up their own state (the `once()` helper in `e2e/phone-keyboard.spec.ts`), so they also run alone.
- **Adding a second module to the e2e needs an unlock seed.** `isModuleUnlocked` wants every earlier module complete, so a fresh context sends Module 2 back to the map. Use `seedPriorModules(context, mod)` from `e2e/lib.ts` (it derives module and project ids from the content). Without it `E2E_MODULE=m02` fails on its first test.
- **Animation e2e (`e2e/animation.spec.ts`).** The player is tested against a small WebM that the spec makes from the committed MP4 with ffmpeg into the OS temp directory (never committed) and serves with `page.route`, including `Range` responses, because seeking needs them (open-source Chromium can't play H.264). An init script makes `canPlayType` refuse MP4, so Google Chrome (which can play H.264) and open-source Chromium take the same path. Pause-prompt tests use `e2e/fixtures/explainer/`, a throwaway Vite server started from the spec on the real `Explainer`, since no lesson has `pauses` yet. Chrome's native arrow-key seek step is its own (about 0.45 s on this clip, not 5 s): assert direction, not size. `steps.json` can have `poster: null`; `end` is the settled frame before the exit fade, so a step is "current" from its `time` until the next step's `time`.
- **Streak e2e (`e2e/streak.spec.ts`).** Fake the clock with `page.clock.install({ time })` before the first `goto`, in a context with `timezoneId: 'Asia/Kolkata'` and a time that is a different calendar day in UTC (20:00 UTC is already the next day there), so a UTC day key fails the test. `clock.fastForward('24:00:00')` fires the chip's one-minute interval once, which is enough to move the page to the next day without a reload; a reload restarts the fake clock. Answer plain multiple-choice warm-up questions only while the clock is faked (no compile). A test that must start from an empty streak with the warm-up kept builds a progress file from `localStorage` with `streak` emptied and uses Settings "Replace my progress". The tests were mutation-checked: a UTC `dayKey` and a `recordAttempt` that skips `noteActivity` each make one fail, and so do a missing reduced-motion rule and a transformation that never records the form it showed. `clock.fastForward('72:00:00')` is rejected as an invalid time (`'48:00:00'` works); pass milliseconds. Settings "Replace my progress" also replaces `streak.longest`, so a test that wants the gallery to keep forms must put the longest run in the file.
