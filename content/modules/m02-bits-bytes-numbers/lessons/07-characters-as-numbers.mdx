C has no separate "character" type. A `char` is a small integer, and a character literal such as `'A'` is just a number: its code in the **ASCII** table, where `'A'` is 65, `'a'` is 97 and `'0'` is 48. The letters and digits sit in runs, so arithmetic on them works. `%c` prints a number as the character with that code, and `%d` prints the number itself. Predict the output.

```c id=char-arith
#include <stdio.h>

int main(void) {
    printf("%d %c\n", 'A', 'A' + 1);
    printf("%d %d\n", 'a' - 'A', '7' - '0');
    return 0;
}
```

The distance from a lower-case letter to its upper-case partner is the same for every letter, and a digit's value is its code minus the code of `'0'`. Those two tricks are all that most character code needs.

Now a surprise. Is `char` signed or unsigned? The C standard does not say: it depends on the platform. On x86-64 Linux, macOS and Windows it is signed. On Linux for ARM64 it is unsigned. The same program can print different numbers, so never rely on `char` for arithmetic with values above 127. Use `unsigned char` or `uint8_t` when you mean a byte.

```c id=char-signed platform predict64=none reason="the answer depends on the CPU family (x86 or Arm), not on 32 versus 64 bits, so there is no useful 64-bit prediction step"
#include <stdio.h>

int main(void) {
    char c = (char)200;
    printf("%d\n", c);
    return 0;
}
```

Look closely at how a number sits in memory. A 32-bit value takes four bytes, and the question is which byte comes first. A machine that stores the **least** significant byte first is **little-endian**, and all the course targets (x86-64, Arm and WebAssembly) do. Its opposite is **big-endian**, and network protocols use it.

Letters beyond ASCII need more than one byte. **UTF-8** is the common encoding: a code point from U+0000 to U+007F is one byte (the same as ASCII), and higher ones take two, three or four. Strings are the subject of Module 4, so here you only look at the bytes of one code point. Try the euro sign, then a letter, then an emoji.

Last, fill in the byte values of a small program. It stores one-byte numbers, and arithmetic on them wraps at 256.

<MemoryDiagram ask={['main.sum', 'main.mask']} line={9}>

```c id=byte-cells trace predict=none
#include <stdint.h>
#include <stdio.h>

int main(void) {
    uint8_t low = 0x4A;
    uint8_t high = 0xC8;
    uint8_t sum = (uint8_t)(low + high);
    uint8_t mask = high & 0x0F;
    printf("%u %u\n", sum, mask);
    return 0;
}
```

**What you know now:** a `char` is a small integer and `'A'` is 65. `c - '0'` turns a digit into its value, plain `char` may be signed or unsigned depending on the platform, and a multi-byte number is stored least significant byte first on every course target. UTF-8 spends one to four bytes per code point.
