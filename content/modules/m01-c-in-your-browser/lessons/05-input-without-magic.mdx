You already used `get_int` in the pyramid and `max3` exercises. It comes from a tiny helper header, **`learnc.h`**, because reading input safely in C takes more machinery than you've learned so far. It's ordinary C (about 100 lines, MIT licence), not a library hiding magic: you'll write your own version in Module 6.

- `int get_int(const char *prompt)` prints the prompt, reads a line, and **asks again** until the whole line is a valid `int`.
- `const char *get_line(const char *prompt)` returns the line you typed, without the `\n`. For now, read `const char *` as "a string" (`printf` prints one with `%s`). It lasts only until your next `get_line` or `get_int`, which overwrite it: use the text before you read again.

When a program reads input in this course, the input typed by the user is shown above the Run button. Input you type isn't part of the program's output, so it doesn't appear in what the program prints.

```c id=get-int-reprompt stdin="abc\n7\n" choices="You typed 7|Number: You typed 7|Number: Number: You typed 7|You typed 0"
#include <stdio.h>
#include "learnc.h"

int main(void) {
    int n = get_int("Number: ");
    printf("You typed %d\n", n);
    return 0;
}
```

The first line, `abc`, isn't a number, so `get_int` printed the prompt a second time and read `7`. Note `#include "learnc.h"` with quotes: by convention quotes mean "a header from my project" and angle brackets mean "a system header".

The standard way to read input is `scanf`. It's powerful but treacherous for beginners: `scanf("%d", &n)` needs that `&`, which you'll understand after Module 6. And when the input doesn't match, it **silently does nothing** and leaves the bad input waiting. Its return value says how many items it actually read, which is why serious code always checks it.

```c id=scanf-returns stdin="hello\n"
#include <stdio.h>

int main(void) {
    int n = 0;
    int got = scanf("%d", &n);
    printf("read %d item(s), n = %d\n", got, n);
    return 0;
}
```
