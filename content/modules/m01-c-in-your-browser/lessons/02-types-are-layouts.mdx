In TypeScript, `let n: number` is a promise to the type checker that disappears at runtime: every `number` is a 64-bit float. In C a type is a **memory layout**. It decides how many bytes a variable occupies, how those bits are interpreted, and which machine instructions operate on it.

The four types you'll use most:

| Type | Typical size | Holds |
|---|---|---|
| `char` | 1 byte | a small integer, used for characters |
| `int` | typically 4 bytes | a whole number, about ±2.1 billion |
| `double` | 8 bytes | a floating-point number (on virtually all platforms the same 64-bit format as JavaScript's `number`) |
| `bool` | typically 1 byte | `true` or `false` (needs `#include <stdbool.h>` in C17) |

`sizeof` tells you how many bytes something takes. `%zu` is the format for its result.

```c id=sizes-basic
#include <stdio.h>
#include <stdbool.h>

int main(void) {
    printf("char %zu, int %zu, double %zu, bool %zu\n",
           sizeof(char), sizeof(int), sizeof(double), sizeof(bool));
    return 0;
}
```

Sizes aren't fixed by the C standard; each platform decides. Here's one that differs between your browser and the 64-bit computer you're probably using. The browser runs a 32-bit target (WebAssembly), where `long` is 4 bytes.

```c id=sizes-long platform predict64="On a 64-bit Mac, Linux or WSL machine, what does the same program print?"
#include <stdio.h>

int main(void) {
    printf("long %zu\n", sizeof(long));
    return 0;
}
```

Arithmetic follows the types of the operands. When **both** operands are integers, `/` is integer division: the fractional part is thrown away, rounding toward zero.

```c id=int-division
#include <stdio.h>

int main(void) {
    printf("%d %d %d\n", 7 / 2, -7 / 2, 7 % 2);
    printf("%.1f\n", 7.0 / 2);
    return 0;
}
```

`%.1f` prints a `double` with one digit after the point. `%` is the remainder.

The surprising part is *where* the truncation happens. Read this carefully: `avg` is a `double`, so will it hold 3.5?

```c id=avg-truncates choices="3.5|3.0|3|0.0"
#include <stdio.h>

int main(void) {
    int total = 7;
    int count = 2;
    double avg = total / count;
    printf("%.1f\n", avg);
    return 0;
}
```

The division `total / count` is computed first, as `int / int`, giving `3`. Only then is that `3` converted to `3.0` to store in `avg`. No warning, no error. To get 3.5, make one operand a `double` *before* dividing: `(double)total / count`. The `(double)` is a **cast**: an explicit conversion.

<Analogy js="Math.trunc(7 / 2)" c="7 / 2" breaksDown="In JavaScript you truncate on purpose. In C it happens implicitly whenever both operands are integers, even when the result is stored into a `double`." />

Format specifiers must match the argument's type: `%d` for `int`, `%f` for `double`, `%c` for `char`, `%zu` for `sizeof`. A mismatch is undefined behaviour, but clang catches it at compile time if you read the warnings.

Underneath, every type is just bits. Try it: type a number and watch its bits, then flip some. An 8-bit `unsigned char` holds 0 to 255. Turn on *signed* and the same bits read as −128 to 127 (Module 2 explains why).

**What you know now:** C types are sizes plus interpretations; `sizeof` reports the size, which varies by platform (`long` is 4 bytes in the browser but 8 on 64-bit Mac and Linux); `int / int` truncates even when you store the result in a `double`; and every `printf` format must match its argument's type, which `-Wall` checks for you.
