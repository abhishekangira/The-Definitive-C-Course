A C function declares its return type and the type of every parameter. Two rules differ from JavaScript:

1. **No hoisting.** The compiler reads top to bottom, so a function must be *declared* before it's called. You either define it above `main`, or write a **prototype** above and the full definition below.
2. **Arguments are copied.** Every parameter receives a copy of the caller's value. Changing the parameter changes the copy, never the caller's variable.

```c id=pass-by-value
#include <stdio.h>

void bump(int n);              // prototype: bump exists, takes an int

int main(void) {
    int x = 41;
    bump(x);
    printf("%d\n", x);
    return 0;
}

void bump(int n) {
    n = n + 1;
    printf("inside bump: %d\n", n);
}
```

Each call gets its own **stack frame**: a block of memory holding that call's parameters and local variables. It's the same idea as the call stack in DevTools, except here it's real memory with real sizes. Step through this program. Before each jump, predict which line runs next.

```c id=add-frames trace predict=none

int add(int a, int b) {
    int sum = a + b;

int main(void) {
    int x = 3;
```

**Scope** is per block: a variable declared inside `{ … }` exists only until the closing brace, like `let`. Unlike `let`, a local variable is **not initialised** for you. Until you assign it, it holds whatever bytes were already in that memory. There is no `undefined`. Reading it is undefined behaviour, so the compiler warns.

<Exercise id="max3" />

**What you know now:** declare before use (prototypes); arguments are copies; each call gets a stack frame that disappears when it returns; locals are scoped to their block and start uninitialised. For named constants, use `#define MAX 10` or an `enum`, never magic numbers.
