In JavaScript you hand source code to an engine like V8, which reads it and runs it, compiling hot paths to machine code on the fly. C works differently: a **compiler** turns your source into a program *before* anything runs. The program is then run directly, with no engine underneath.

In this course the compiler is **clang**, the same compiler family that ships with macOS (Apple builds its own version of clang). It runs right here in your browser, so you can start without installing anything.

Here is a complete C program. Before you run it, commit to a prediction: what exactly will it print?

```c id=hello-two-lines
#include <stdio.h>

int main(void) {
    printf("Hello, world!\n");
    printf("%d + %d = %d\n", 2, 2, 2 + 2);
    return 0;
}
```

Line by line:

- `#include <stdio.h>` pastes in the *declarations* of the standard input/output functions, including `printf`. Without it the compiler doesn't know what `printf` is.
- `int main(void)` is where every C program starts. It takes no arguments (`void`) and returns an `int`.
- `printf` prints a **format string**. `\n` is a newline (nothing adds one for you), and each `%d` is replaced by the next argument, printed as a decimal integer.
- `return 0;` ends `main` and hands **exit status** 0 back to whatever started the program. By convention 0 means success and anything else means failure.
- Every statement ends with `;`. Unlike JavaScript there is no automatic semicolon insertion.

So what happened when you pressed Run? Two separate programs did their jobs: clang compiled your code, then your compiled program ran.

**What you know now:** a C program is compiled ahead of time into a separate executable; `main` is the entry point and its return value is the exit status; `printf` prints a format string whose `%` directives must match their arguments; and `#include` pastes text.
