# src/: the app

Notes for anything under `src/`. Three folders have their own notes as well: `progress/AGENTS.md` (the progress document, gating, local tasks and the streak), `runtime/AGENTS.md` (the in-browser compiler and runtime) and `tutor/AGENTS.md` (the optional AI tutor). `testing/` must stay free of DOM and Node APIs, because `check.mjs` and the browser share it (`testing/boundaries.test.ts` checks this). Never edit `generated/` by hand (root `AGENTS.md`, "Generated files").

- **Routing.** HashRouter with Vite `base: './'`. The toolchain URL is resolved on the main thread and passed to the workers.
- **Unreleased modules.** `available: false` in `content/course.yaml` means not released. `buildRegistry` (`content-runtime/release.ts`) leaves such a module out of `modules`, so gating, "up next", the map and every page treat it as absent, and its exercises stay out of the global `exercises` index (their folder names are global: two modules with one name would replace each other). `?preview=m03` in the page URL, before the `#`, opens it behind a "Preview" banner, and the progress store then writes only `tdcc:v1:progress-preview` (`progress/AGENTS.md`). Why this design: `docs/adr/0004-unreleased-modules.md`. To test against a draft, build the mocked `modules` with the real `buildRegistry` (as `progress/gating.test.ts` does) or use the fixture server of `e2e/unreleased-modules.spec.ts`.
- **Native sessions** (`docs/adr/0005-native-sessions.md`). `sessionsFor(module)` (`content-runtime/course.ts`) lazy-loads `src/generated/sessions/<module>.json`, and the lesson page hands it to `useSessions()` with the samples; `<Transcript>` (`components/Transcript.tsx`, choices in `transcript-tabs.ts`) shows it: "No stored run" only for a platform in the session's `platforms` with no run (a gcc-only gdb session is not missing anything; `transcript-tabs.test.ts` and `Transcript.dom.test.ts` cover both cases), a plain label instead of a one-tab tab bar, and `white-space: pre` in a focusable, named box that scrolls sideways (`e2e/transcript.spec.ts` presses ArrowRight at 390 px), with an always-drawn scrollbar, a faded edge on each side that hides text (`data-hidden-left/right` on the frame) and a "Wrap lines" toggle (`aria-pressed`, off by default; each output line is a block so a wrapped line hangs 4ch under its start). `LessonPage` clears samples and sessions when the lesson or module changes and ignores a load that finishes after it changed again (`LessonPage.dom.test.ts`). `<CompilerError session="id" step stage fix>` (`interactions/CompilerError.tsx`, grading in `report-questions.ts`) shows a report the same way and asks which line (a first user frame: the first `file:line` naming one of the session's `sources`, on any platform's report, so the tab on screen doesn't change the answer), what is wrong, and which stage failed (`stage="link"` asks no line), numbered in plain legend text (`InlineMarkdown`, never `MiniMarkdown`, whose `1. ` starts a list); the fix is checked in the browser with the guardrail UBSan runtime (`fix="ubsan"`), leakcheck (`"leak"`) or a clean compile (`"compile"`), and needs a one-`.c` session. Quizzes (`app/pages/QuizRunner.tsx`, `QuizItems.tsx`; answer keys in `interactions/quiz-answers.ts`, shared with lint and e2e) load the same file: a `ce` with `session` shows the report in a `TranscriptPane` and asks what is wrong and, with `stage`, which stage failed; an `order` with `session` is graded against the stored run's commands (identical on every stored platform, else the item says so), shows no transcript until answered (it would give the order away), then marks each place and shows the run; an `sp` shows a gdb trace paused before `line` with its call stack and asks two numbered parts: the line one `step` later (`spSteps`: the next trace step, since the tracer records `step`) and the stack after it, out of three (`spStackOptions`: after `step`, before it, and after `next`, which is the first later step no deeper than the current one); when two of those stacks are equal the item shows an alert instead (lint reports it). No content module has a session yet, so the test data is tools/verify's output for the m97 fixture module, committed as `tools/verify/fixtures/generated/sessions/m97.json` and regenerated by `tools/verify/verify.test.ts`, which fails when it differs (CI is the reference; take the fresh file from a CI run's `test-results/session-fixtures/`). Never edit it by hand.
- **Playground.** `#/playground` (`src/app/pages/PlaygroundPage.tsx`) is a free, ungated C editor on the same compiler and runtime as the lessons. It records no progress. Its draft (code, stdin, arguments, the UBSan switch) lives in its own key `tdcc:v1:playground`, which progress export, import and "Delete all progress" leave alone. It is saved only after this tab edited it (a second, untouched tab never overwrites it) and not at all above 200,000 characters, because it shares the browser's storage quota with progress. Low-memory mode disables Run there, because there is no stored output for arbitrary code. `e2e/playground.spec.ts` covers it.
- **Look and feel** (taste-skill's "achromatic ledger" style, 2026-10-20). The chrome is ink on a cool grey ground with white surfaces; the one hue, `--data` (a blue), marks data (progress cells, the current step, the traced line, focus); status uses the pale pairs `--ok|warn|err-soft` with `-ink` text. Surfaces are told apart by a tone step or a 1px `--border`, never a shadow, gradient, glow, glass or opacity (only the Rio transformation animation keeps its glow). Radii are tight (cards 8, controls 6, chips 4). Links are ink and underlined. The primary button is near-black (inverted in dark). Type is Geist and Geist Mono, self-hosted through `@fontsource-variable/*` (OFL-1.1, no request leaves the site): sentence case, no tracked capitals, weights 400 to 600. The shell is a 48px bar on the page ground over one centred 1120px column (`--column`); pages use a 12-column grid, the lesson page a 760px reading column plus a module rail, settings are label-and-panel rows (`.setting` in `base.css`). All tokens live in `src/styles/tokens.css`; `tokens.test.ts` reads that file and fails if a text pair drops under 4.5:1 or a control edge or the focus ring under 3:1, in light or dark. Add a colour to the tokens, not to a component. The product's own marks are `BrandMark` (a C in seven bit cells; `index.html` draws the favicon from the same cells) and `Cells` (progress as one cell per step). "Up next" on the course map comes from `nextStep` (`src/progress/next.ts`): warm-up, then lessons, project, checkpoint, module by module.
- **Untrusted input is covered by `src/untrusted-input.test.ts`.** `migrate()` rebuilds the progress document from a whitelist (JSON.parse makes `__proto__` an own key; assigning it later swaps an object's prototype), so new progress fields must be added to `migrate` too or an import silently drops them. Import files go through `parseProgressFile` (size cap). Store the canonical `formatCode(...)` of a pasted code, never the raw paste. Regexes anchored at `$` with a `[...]+` run (like the trailing-punctuation trim in `parseCode`) are quadratic on long input: cap the input first. Timing tests must not use a wall-clock cap alone (they flake under load): compare the time at N with the time at 4N, best of 3. Progress keys are data: look them up with `Object.hasOwn`, because `cards['constructor']` finds `Object.prototype.constructor` and `exercises['toString']` yields NaN. In MiniMarkdown a `[^x]+` run followed by a literal that can fail is quadratic on `[[[[…`: exclude the opening character from the class.
- **Component wiring tests** live in `src/untrusted-input-wiring.test.ts`: `// @vitest-environment jsdom` (`jsdom` is pinned in devDependencies and needs Node ≥22.22.2, which `engines` in package.json now requires; CI's `node-version: 22` resolves to 22.23.3) plus `react-dom/client` and `act`. No shipped content uses `LocalTask` (native exercises), so Playwright cannot reach it. Vitest only collects `src/**/*.test.ts` and `tools/**/*.test.ts` (`vite.config.ts`); a `.tsx` test file is never run.
- **CSS `transform-origin` also moves an SVG element's `transform` attribute.** With `transform-box: fill-box` on a class, an element that also has a `transform="..."` attribute is scaled around its own box and lands in the wrong place; put the attribute on a wrapper `<g>` and the animated class inside it.
- **`prefers-reduced-motion` is not enough for infinite animations.** The global rule in `base.css` sets `animation-duration: 0.01ms`, which makes an infinite animation flicker; a component with its own looping motion (`StreakWarrior.module.css`) must also set `animation: none` in its own media query, and draw every part at full size without the animation (a part that starts at `scale(0)` would vanish).
