# src/progress/: the progress document, gating and the streak

These notes also cover the components that read the document: `LocalTask` (`src/interactions/`) and `StreakChip`, `StreakWarrior` and `WarriorArt` (`src/components/`). Untrusted-input rules for imports and pasted codes are in `src/AGENTS.md`.

- **Progress schema** (`store.ts`): one JSON document at `tdcc:v1:progress` (`version, seed, cards, lessons, samples, exercises, quizzes, projects, settings, streak`). Gating rules live in `gating.ts`. A new field must be added to the `migrate` whitelist, to `mergeProgress`, to the round-trip test in `store.test.ts` and to the exact key list in `src/untrusted-input.test.ts`, or an import silently drops it.
- **Previewing an unreleased module** (`?preview=m03`, `src/AGENTS.md`): the store's key becomes `tdcc:v1:progress-preview`. `load()` merges that document over the real one with `mergeProgress` (so the real learner seed and earlier modules count), and every write, Settings import, merge and reset goes to the preview key only; the real `tdcc:v1:progress` is never written, so nothing from a half-built module reaches it. Settings and the export date chosen in the preview are laid back over the merge (`mergeProgress` alone would take the real ones), and `replaceProgress` on an ordinary page (Settings reset or import) also deletes the preview document, which holds a copy of the old progress. `store.preview.test.ts` covers it.
- `update()` in the progress store is a no-op when nothing changed. Keep effects idempotent: an effect that always writes state loops forever (React error 185).
- **LT solution and variants.** Same gate as a browser exercise (`solutionGate`): all three hints, then two distinct source hashes (`src`; `check.mjs` increments `run` every full run and the MAC changes with it, so the same program prints a new code), or one code plus 20 minutes when `activeMs` is already stored. `recordLocalCode` counts distinct `src` values and stores each canonical code once. The lock text never names minutes, because this panel never adds time. "Show the reference solution" sets `solutionViewed`, moves focus to the solution, and shows `solution.c`. A later progress paste says to keep going; it does not repeat that the solution is newly available. "Start the variant" focuses and announces that box (`role="status"`). A variant allows hints 1–2 only and never a solution; its completion token sets the parent's `mastered` unless that variant's solution was viewed. `attempts` counts accepted pastes, not the runner's run index. `migrate` (load and import) and `mergeProgress` lower `substantive` to the distinct `src` count when progress codes are stored, and never raise it, so a document that counted code strings does not stay unlocked. Checkpoints pass `assessment`, which hides hints, the solution and the variant, and a variant completion there does not master the parent (the checkpoint's `onPassed` records the answer). Native projects offer no solution. No lesson ships an LT exercise until Module 3, so Playwright cannot open this panel; `src/interactions/LocalTask.variants.test.ts` drives the fixture `tools/exercises/fixtures/.../lt-free-list`.
- **Streak, spirit beans and Rio.** `streak.ts` keeps only the local `YYYY-MM-DD` days with a submission (plus the longest run); the current streak is derived from them and "today" (`streakStatus`), so there is no timer and it survives export, import and merge. Spirit beans are derived the same way, by replaying the days: one to start, one more on every 7th day of a streak, at most 3; a bean saves one missed day (it bridges the streak but adds no day) and is used up only when it saves it, so a longer gap ends the streak and keeps the beans. A submission is a problem check (pass or fail: `useExerciseProgress.recordAttempt`), a valid `LocalTask` paste, a quiz answer or a finished checkpoint; call `noteActivity(p)` inside the same `update` for any new kind of submission. Lesson predictions, hints and the Playground never count. `StreakChip` (header: Rio's head and the days, hidden when no streak runs, dashed while today's submission is missing) and the Settings panel read it. `warrior.ts` maps the current streak to Rio's form (kid, then Warrior at 3, Golden Warrior 7, Golden Mane 14, Crimson Fur 30, Great Ape 50 days; a broken streak is the defeated kid) and the mood (defeated, worried, ready); the Settings gallery keeps every form the longest streak reached. `StreakWarrior.tsx` plays a transformation the first time a higher form is shown and announces it; the form last shown is in its own key `tdcc:v1:warrior` (outside the progress document, like the playground draft). Rio is original pixel art, an homage with original names (the client's choice; ripped game sprites or official art could not be published under this public repo's MIT licence): the pixels are ASCII rows in `src/components/warrior-sprites.ts` (one character per pixel, a 96 x 96 grid, mood and blink frames as patches drawn over a sprite), and `WarriorArt.tsx` turns them into SVG paths and computes the aura, the dark-page rim, the shadow and the night sky. Motion is CSS in whole-pixel steps, off under `.still` and `prefers-reduced-motion`; colours are fixed hex values. The streak's e2e tests are described in `e2e/AGENTS.md`.
