# src/progress/: the progress document, gating and the streak

These notes also cover the components that read the document: `LocalTask` (`src/interactions/`) and `StreakChip`, `StreakWarrior` and `WarriorArt` (`src/components/`). Untrusted-input rules for imports and pasted codes are in `src/AGENTS.md`.

- **Progress schema** (`store.ts`): one JSON document at `tdcc:v1:progress` (`version, seed, cards, lessons, samples, exercises, quizzes, projects, settings, streak`). Gating rules live in `gating.ts`. A new field must be added to the `migrate` whitelist, to `mergeProgress`, to the round-trip test in `store.test.ts` and to the exact key list in `src/untrusted-input.test.ts`, or an import silently drops it.
- **Previewing an unreleased module** (`?preview=m03`, `src/AGENTS.md`): the store's key becomes `tdcc:v1:progress-preview`. `load()` merges that document over the real one with `mergeProgress` (so the real learner seed and earlier modules count), and every write, Settings import, merge and reset goes to the preview key only; the real `tdcc:v1:progress` is never written, so nothing from a half-built module reaches it. Settings and the export date chosen in the preview are laid back over the merge (`mergeProgress` alone would take the real ones), and `replaceProgress` on an ordinary page (Settings reset or import) also deletes the preview document, which holds a copy of the old progress. While previewing, Settings export, import and reset are off (`previewing` in `store.ts`, `SettingsPage`, and the export reminder in `Layout`), and anything new that sends the document out of the page must check `previewing` and stay off too, or it carries draft progress into the real progress elsewhere (Drive sync does: `syncNow` in `drive.ts` returns first thing, and `DriveSyncPanel` shows a note instead of its buttons). `store.preview.test.ts`, `drive.preview.test.ts` and `e2e/unreleased-modules.spec.ts` cover it.
- **Google Drive sync** (`drive.ts`, UI in `src/components/DriveSyncPanel.tsx`, started from `main.tsx`). Opt-in; hidden unless the build sets `VITE_GOOGLE_CLIENT_ID` (CI passes the repository variable `GOOGLE_CLIENT_ID`; the owner creates a Web OAuth client in Google Cloud with the authorised JavaScript origins `https://abhishekangira.github.io` and `http://localhost:5173` (`npm run dev`) and the Drive API enabled; `docs/adr/0003-google-drive-sync.md`). Its state (connected, the short-lived token and its expiry, the file id, the last sync, `replaceNext`, the epoch) is its own key `tdcc:v1:drive`, outside the document and shared by every tab. Every sync is pull, `reconcile` (`mergeProgress` with the Drive copy as the base, so its seed wins, and this browser's `settings`), apply, push; `syncOnce` is pure apart from `fetch` and is tested against a fake Drive in `drive.test.ts`. Anything that replaces the document instead of merging (Reset, "Replace my progress") must call `replaceDriveOnNextSync()`, or the next merge brings the old progress back; it writes a new `driveEpoch` into the Drive file, and a browser that sees an epoch it has not synced with adopts the Drive copy instead of merging. Tabs: only the tab that made a change autosaves it (`subscribeProgress` passes `'storage'` for another tab's write), and a round stops before merging when the shared settings show another tab's Reset (`roundCancelled`, `replaceNextAfter`). An empty Drive file (created, but the upload into it failed) counts as no copy. The Google sign-in script loads only on pointer or focus over a sign-in button, so the click keeps its user activation for the popup. CI's build has the client id, so the panel renders in e2e: `e2e/drive-sync.spec.ts` stubs Google with `context.route` and skips when `dist/` was built without an id (`VITE_GOOGLE_CLIENT_ID=x.apps.googleusercontent.com npm run build` to run it locally).
- `update()` in the progress store is a no-op when nothing changed. Keep effects idempotent: an effect that always writes state loops forever (React error 185).
- **LT solution and variants.** Same gate as a browser exercise (`solutionGate`): all three hints, then two distinct source hashes (`src`; `check.mjs` increments `run` every full run and the MAC changes with it, so the same program prints a new code), or one code plus 20 minutes when `activeMs` is already stored. `recordLocalCode` counts distinct `src` values and stores each canonical code once. The lock text never names minutes, because this panel never adds time. "Show the reference solution" sets `solutionViewed`, moves focus to the solution, and shows `solution.c`. A later progress paste says to keep going; it does not repeat that the solution is newly available. "Start the variant" focuses and announces that box (`role="status"`). A variant allows hints 1–2 only and never a solution; its completion token sets the parent's `mastered` unless that variant's solution was viewed. `attempts` counts accepted pastes, not the runner's run index. `migrate` (load and import) and `mergeProgress` lower `substantive` to the distinct `src` count when progress codes are stored, and never raise it, so a document that counted code strings does not stay unlocked. Checkpoints pass `assessment`, which hides hints, the solution and the variant, and a variant completion there does not master the parent (the checkpoint's `onPassed` records the answer). Native projects offer no solution. No lesson ships an LT exercise until Module 3, so Playwright cannot open this panel; `src/interactions/LocalTask.variants.test.ts` drives the fixture `tools/exercises/fixtures/.../lt-free-list`.
- **Streak, spirit beans and Rio.** `streak.ts` keeps only the local `YYYY-MM-DD` days with a submission (plus the longest run); the current streak is derived from them and "today" (`streakStatus`), so there is no timer and it survives export, import and merge. Spirit beans are derived the same way, by replaying the days: one to start, one more on every 7th day of a streak, at most 3; a bean saves one missed day (it bridges the streak but adds no day) and is used up only when it saves it, so a longer gap ends the streak and keeps the beans. A submission is a problem check (pass or fail: `useExerciseProgress.recordAttempt`), a valid `LocalTask` paste, a quiz answer or a finished checkpoint; call `noteActivity(p)` inside the same `update` for any new kind of submission. Lesson predictions, hints and the Playground never count. `StreakChip` (header: Rio's head and the days, hidden when no streak runs, dashed while today's submission is missing) and the Settings panel read it. `warrior.ts` maps the current streak to Rio's form (kid, then Warrior at 3, Golden Warrior 7, Golden Mane 14, Crimson Fur 30, Great Ape 50 days; a broken streak is the defeated kid) and the mood (defeated, worried, ready); the Settings gallery keeps every form the longest streak reached. `StreakWarrior.tsx` plays a transformation the first time a higher form is shown and announces it; the form last shown is in its own key `tdcc:v1:warrior` (outside the progress document, like the playground draft). Rio is original pixel art, an homage with original names (the client's choice; ripped game sprites or official art could not be published under this public repo's MIT licence): the pixels are ASCII rows in `src/components/warrior-sprites.ts` (one character per pixel, a 96 x 96 grid). `.` is empty (transparent on a sprite, unchanged on a patch) and a space (`ERASE`) paints transparent, so a patch can erase. `FORM_FRAMES` lists each form's frames: `idle` (the first frame is what `.still`, the gallery and the header head show), and `defeated` and `worried` where that pose has its own drawing; a blink is one patch over the idle frames. A loop frame is a full sprite or patches over one. `WarriorArt.tsx` turns a frame into SVG paths and computes the aura (four frames: an inner glow, outer flame tongues that shift up in whole pixels, and particles that rise the same way), the dark-page rim, the shadow and the night sky. `<WarriorArt form mood aura="none|flicker|blaze" />` is also a prop of `WarriorPortrait`. Leaving `aura` out is flicker for golden, mane and crimson and none for kid, warrior and ape (`defaultAura`); `aura="blaze"` draws the full fire on every form, including kid, warrior and ape. `bare` still draws no aura (the header and a locked gallery silhouette). #106 should pass `aura` and not redraw sprites. Motion is CSS in whole-pixel steps, off under `.still` and `prefers-reduced-motion`; a pose with several frames plays that list instead of the 1px bob. Colours are fixed hex values. The streak's e2e tests are described in `e2e/AGENTS.md`.
