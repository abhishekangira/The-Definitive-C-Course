# Animations

One **self-contained HyperFrames project per animation** (`animations/aNN-topic/`). The editable source is HTML + GSAP;
what ships to learners is a **rendered MP4** with a poster, step stills, WebVTT captions, a transcript and a `steps.json`,
all generated by `npm run anim:render` into `public/animations/<id>/` and played by the app's `<Explainer>` over a native
`<video>`. Nothing from HyperFrames or GSAP reaches the learner's browser.

| Animation | Lesson | Length | Shows |
|---|---|---|---|
| `a01-press-run` | 1.1 | 45 s | Press Run: source, clang in a Web Worker (itself WebAssembly), link, a fresh worker runs `main.wasm`, WASI `fd_write`, the output panel, then the native contrast (x86-64/arm64) |
| `a02-build-and-load` | 3.2 | 75 s | hello.c on x86-64 Linux gcc 13: preprocess, compile, assemble, link, and load (`nm` still `U printf` after link; the dynamic loader fills it in) |
| `a03-twos-complement-wheel` | 2.3 | 45 s | An 8-bit counter as a ring (253 to 255 to 0), the same bits read as signed (`1111 1011` is -5), unsigned wrap (`250 + 10` is 4) against signed overflow (the browser checker's report) |
| `a04-float-fields` | 2.5 | 60 s | A float as sign, exponent and fraction: `0x3F800000` is 1, `0x3DCCCCCD` is the float nearest 0.1, and `0.1 + 0.2` as a double |

The full list (A1 to A24) is in `PLAN.md` section 8.

## Commands

```bash
# Environment for every hyperframes call (tools/anim sets these itself; set them when you run the CLI by hand):
export HYPERFRAMES_NO_TELEMETRY=1 HYPERFRAMES_SKIP_SKILLS=1 HYPERFRAMES_NO_UPDATE_CHECK=1
export HYPERFRAMES_BROWSER_PATH=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell

npm run anim:check                  # every project: static rules + hyperframes lint + check --strict + render freshness
node tools/anim/check.mjs --static  # the same without a browser (seconds): validation, lint, manifest freshness
npm run anim:render                 # render what changed (hash-cached) into public/animations/<id>/ and update manifest.json
node tools/anim/render.mjs a01 --force      # re-render one project (ids and flags in any order)
node tools/anim/render.mjs --dry-run        # say what is stale
node tools/anim/render.mjs --webm dist/animations   # deploy step: transcode the committed MP4s to VP9 WebM (not committed)
node tools/anim/sync-shared.mjs     # copy _shared/vendor and _shared/fonts into the projects (check and render do it for you)
npx vitest run tools/anim           # the pipeline's unit tests and the A1 facts test
```

The CLI is run as `npx --yes hyperframes@0.8.162` (pinned in `tools/anim/lib.mjs`; it is a 157 MB dev tool and is
deliberately **not** in `package.json`). It needs Node ≥22 and FFmpeg. Chromium comes from `/opt/pw-browsers` (do not run `playwright install`).
Pixels can differ between Chrome versions, so each manifest entry records the browser it was rendered with and
`render.mjs` re-renders when it changes. A1 (45 s) renders in about 3 minutes here (the CLI chose 1 capture worker on this 4-core
container: software GL), and a render of unchanged sources is skipped.

Skipped on purpose (they are interactive or online): the skills' intent interview and `BRIEF.md`, `usage`,
`publish`, `auth`, `open`, `feedback`, `skills update`, cloud renders.

## What CI runs

CI (`.github/workflows/ci.yml`) runs `node tools/anim/check.mjs --static` only: static validation, `hyperframes lint` and
manifest freshness, with no browser. The full `npm run anim:check` needs Chromium and a network download of the pinned
`hyperframes` CLI, and the manifest records the exact browser build the MP4s were rendered with, so a different Chromium on
the runner would report stale renders. Run the full check locally when you touch an animation. A separate CI step transcodes
the committed MP4s with `node tools/anim/render.mjs --webm dist/animations` (the only WebM step). It has no `if:`, so it
runs on every CI run including PRs; only the artifact upload and the Pages deploy are main-only.

## Layout and naming

```
animations/
  README.md
  manifest.json                  generated: sourceHash + browser + sha256 of every output, per animation
  .gitignore                     ignores the synced copies below
  _shared/vendor/gsap.min.js     canonical GSAP 3.15.0 (license header intact; see vendor/README.md)
  _shared/fonts/*.woff2, OFL.txt Inter 400/700/800 and JetBrains Mono 400/700, latin subsets (OFL 1.1)
  a01-press-run/                 aNN-kebab-topic: the directory name is the project id and the root composition id
    index.html                   standalone root: @font-face, shared CSS, vendored GSAP, scene hosts, EMPTY root timeline
    compositions/pr-00-bg.html   persistent layers: <abbr>-00-<layer>
    compositions/pr-00-rail.html
    compositions/pr-01-source.html ... pr-06-native.html     one scene per file: <abbr>-NN-<scene>
    index.motion.json            motion assertions (appearsBy per step, before, staysInFrame)
    captions.json                cues: [{ step, start, end, text }], global seconds
    animation.json               title, lesson, platform note, description (text alternative), optional posterAt
    vendor/, assets/fonts/       SYNCED from _shared, GITIGNORED (check and render run sync-shared first)
    .hyperframes/, renders/      tool output, gitignored
public/animations/<id>/          generated and COMMITTED: <id>.mp4, poster.webp, steps.json, <id>.vtt, transcript.txt, stills/<step>.webp
```

* **Id**: `aNN-kebab-topic` (`a07-merge-sort`). **Abbreviation**: 2 to 4 letters, unique per animation (`pr` for press-run).
* **Scene id = file name = host `data-composition-id` = inner root id = `window.__timelines` key** (`pr-02-compile`).
  Persistent layers use `00` (`pr-00-bg`, `pr-00-rail`); scenes are numbered in order.
* **Element ids and classes** inside a scene are prefixed with the scene number (`pr02-worker`, `.pr02-d`); shared classes
  in `index.html` start with `pr-`. Ids are unique across the assembled page, and motion selectors are single `#ids`.
* **Step keys** are lowercase verbs or nouns (`source`, `compile`, `link`, `run`, `output`, `native`) and are the same in
  the scene's `data-steps`, its `tl.addLabel("<key>", ...)`, the rail, the motion sidecar and `captions.json`.
* **Synced copies are gitignored** (they would be 24 copies of GSAP and the fonts). A fresh clone needs no manual step:
  `check` and `render` sync first. HyperFrames lint forbids `../` asset paths, which is why the copies exist at all.

## Authoring rules

Enforced by `hyperframes lint` / `check`, by `tools/anim/validate.mjs`, or by review. `validate.mjs` fails the build on
anything marked (v). Every rule has a test that breaks it (`tools/anim/anim.test.ts`).

**Structure**
1. The root `index.html` is thin and standalone (no `<template>`): fonts, shared CSS, GSAP, scene hosts, and an empty
   paused timeline. **Every scene is a sub-composition** in `compositions/` (v). 1920x1080, 30 fps (v).
2. A scene file is exactly one `<template>` holding its `<style>`, its root `<div id="root" data-composition-id="...">` and
   its `<script>`. Style the root through `#root`, never a class. The host in `index.html` carries `data-start`,
   `data-duration`, `data-width`, `data-height`, `data-track-kind="graphics"` (v).
3. **Step labels are mirrored in `data-steps`** (v): the scene root declares
   `data-steps='{"compile":{"label":"Compile","start":0,"end":10.45}}'` in scene-local seconds, the script reads it with
   `JSON.parse` and calls `tl.addLabel(key, start)`. `end` is the moment the step is *settled* (before the exit fade);
   stills and pause-at-step prompts use it. The persistent rail repeats the **global** times in `data-rail-steps`; a
   mismatch fails `anim:check` (v).

**Timelines and motion**
4. **Exactly one paused GSAP timeline per file**, built in an IIFE and **registered last** with
   `window.__timelines = window.__timelines || {}; window.__timelines["<id>"] = tl;`. The guard is mandatory: the
   skills say it is optional, but `@hyperframes/player` injects its runtime after load and throws without it (v).
   Never `play()`, never nest timelines, keep the root timeline empty.
5. **`fromTo` only**, with explicit start values and positions or labels (v). When an element has several `fromTo`
   calls, every one except the earliest needs `immediateRender: false` (lint: `gsap_repeated_fromto_without_baseline`).
6. **Animate transforms (`x`, `y`, `scale`, `rotation`, ...), `opacity`, colours and SVG `strokeDashoffset` only** (v).
   Never `width`, `height`, `top`, `left`, `margin`, `padding`, `fontSize`, `letterSpacing`, `display`, `visibility`,
   `delay`, callbacks or `repeat: -1` (v). Never put a CSS `transform` on an element GSAP transforms, never tween a
   clip's visibility, no CSS transitions or keyframes (v).
7. **No clocks, `Math.random`, timers, rAF, event listeners, network, CDN or any `http(s)://` URL** (v). Repeats are
   finite and finish before the scene ends. Measure the DOM only at setup, or avoid measuring: arrows use
   `pathLength="1"` with `stroke-dasharray: 1 1.5` and tween `strokeDashoffset` from 1 to 0.
8. **Keep the background cheap.** A static grid with moving soft gradients costs nothing; a drifting grid of thin lines
   cost 30% more bytes at CRF 30 (617 KB vs 444 KB over 12 s, measured). Do not animate full-frame fine detail.

**Look**
9. **Fonts**: only the shipped woff2 files, declared with `@font-face` in `index.html`. The latin subsets have **no arrows
   or math symbols** (`->`, `≥`, `≈`, check marks): draw them as SVG or use words (v: `validate.mjs` rejects any
   character outside the subset, because the fallback font differs per machine and breaks determinism).
10. **Text is at least 24 px** at 1080p (v, px sizes only): labels 24 to 32, body 26 to 36, code 28 to 40, headlines 64.
    Everything stays inside the **title-safe area** (x 192 to 1728, y 108 to 972; only backgrounds bleed). Contrast is
    WCAG AA (`check` enforces it as an error).
11. **One dark render** per animation, shown as-is in both app themes (PLAN section 12). The palette is the app's dark
    theme tokens, declared once as CSS custom properties in `index.html`. Colour says who is acting, and is used the same
    way in every animation: page = blue, compiler = violet, program = green, native toolchain/OS = orange, warning = amber.
12. **Silent, captions as a sidecar.** Never burn captions into the frames. One cue per step in `captions.json` (two only
    if a step is longer than 10 s), at most 22 characters per second (warning above that), 220 characters per cue.
13. **Values shown on screen come from running code.** `tools/anim/a01-facts.test.ts` compiles and runs the program A1
    displays and checks every number, byte and message on screen against the real toolchain. Do the same for any new
    animation that shows a diagnostic, an output, a size or an address, and say which platform it depicts in
    `animation.json` (`platform`). Values that vary by platform come from the verify pipeline through composition
    variables: `variables.json` next to `index.html` is passed as `--variables-file` with `--strict-variables`.

**Gates (Definition of done for an animation)**
14. `npm run anim:check` passes: static validation, `hyperframes lint` (0 errors, 0 warnings), `hyperframes check --strict`
    (runtime, layout, `index.motion.json`, contrast) sampled at every step's settled frame and midpoint.
15. `index.motion.json` has an `appearsBy` for **each step** (its `bySec` inside the step's window), `before` ordering across
    scenes and `staysInFrame` for the main containers; selectors match exactly one element (v).
16. Look at the snapshots yourself: `npx --yes hyperframes@0.8.162 snapshot animations/<id> --at <times> -o <tmpdir>`.
17. `npm run anim:render`, then check `ffprobe`: duration equals `data-duration` and frames equal duration x fps
    (`render.mjs` fails otherwise). Commit the MP4 and its sidecars with `manifest.json`.

## How steps and captions reach the app

```
scene data-steps (local) + host data-start ──► steps[] { key, label, time, end }   ─┐
captions.json ───────────────────────────────► <id>.vtt, transcript.txt             ├─► public/animations/<id>/steps.json
animation.json (title, lesson, platform, description, posterAt) ──────────────────────┘
snapshots at each step's `end` and at `posterAt` ─► stills/<step>.webp, poster.webp (not from the CRF 30 video)
```

`steps.json` (A1):

```json
{ "id": "a01-press-run", "title": "...", "lesson": "1.1", "platform": "...", "description": "...",
  "duration": 45, "fps": 30, "width": 1920, "height": 1080,
  "video": "a01-press-run.mp4", "poster": "poster.webp", "captions": "a01-press-run.vtt", "transcript": "transcript.txt",
  "steps": [ { "key": "source", "label": "Source", "time": 0, "end": 5.45 }, ... ],
  "stills": { "source": "stills/source.webp", ... } }
```

* `time` is where the step's chip seeks to; `end` is the settled frame: pause there for a prediction prompt and use the
  matching `stills/<key>.webp` for the reduced-motion sequence.
* `<id>.vtt` is a `captions` track (shown by default, never burned in); `transcript.txt` is the same text, with the step
  label above each paragraph; `description` is the long text alternative for screen readers.
* The MP4 is H.264 High, yuv420p, CRF 30, metadata stripped, `faststart`. Browsers without H.264 (open-source Chromium
  builds) get a **WebM** that `render.mjs --webm <dir>` transcodes from the MP4 during the deploy build (VP9, CRF 36; 17 s for A1).
  Tests in headless Chromium should use a WebM.

## Caching and the manifest

`animations/manifest.json` maps each animation to `sourceHash`, `browser` and the sha256 of every file in
`public/animations/<id>/`. `sourceHash` covers every project file (after sync, so the vendored GSAP and fonts count),
the pinned CLI version, the render flags and the pipeline version. `anim:check` fails when:

* the sources, CLI version or flags changed since the render ("STALE"; run `npm run anim:render`),
* an output file is missing, edited by hand or unexpected, or
* a rendered folder or manifest entry has no project.

`anim:render` skips a project when `sourceHash` and `browser` match and the outputs are intact. The poster, the stills,
`steps.json`, the VTT and the transcript are byte-identical across renders; the MP4 is not. Repeated renders on one
machine with one Chrome build (Google Chrome 155.0.8059.84) differ in pixels: for A2, decoded frames
(`ffmpeg -f framemd5`) differed from frame 653 on, lowest PSNR 43.7 dB (invisible). A3 behaved the same (two `--force`
renders gave two MP4s, neither matching main's). `--workers 1` and unsetting `DISPLAY` did not help. Byte-identical
outputs across two `--force` runs were observed once for A1, on another machine. CI checks the committed files against
`manifest.json` and never re-renders, so a re-render that produces a different MP4 is safe, but only re-render an
animation whose sources changed, and commit only the ids you authored.

Measured for A1: MP4 1.55 MB (289 kbit/s, CRF 30); poster 34 KB; six stills 49 to 78 KB each; WebM (VP9, CRF 36,
`-deadline realtime -cpu-used 8`) 2.7 MB in 17 s. `-deadline good` is 4 to 5 times slower and not smaller on this
content, so the deploy transcode uses the fast preset.

## Gotchas found while building A1

* The runtime moves the scene root's attributes onto an inner `div` (`data-hf-inner-root`) and drops its `id` and
  `data-composition-id`, so `document.querySelector('[data-composition-id="x"]')` returns the *host*. Scene scripts find
  their root by looking for their own attribute (`data-steps`) on the host or inside it (see any scene).
* `white-space: pre` on a container that holds block children also preserves the newlines in your markup between them
  and doubles the line spacing. Put `white-space: pre` on the leaf spans.
* `gsap.fromTo` applies its from-values at authoring time. A later `fromTo` on the same element needs
  `immediateRender: false`, and an element that must be hidden before its first tween needs `opacity: 0` in CSS when
  its first tween is `immediateRender: false`.
* `hyperframes check` samples contrast at only five of the `--at` times and runs the layout audit at the others; the
  motion sidecar runs 300 samples regardless. `tools/anim/check.mjs` passes every step's end and midpoint.
* A render started from a shell that exits is cancelled (`render_cancelled_parent_exited`). Keep the render's parent alive.
* Fonts that are not declared with `@font-face` are fetched from Google Fonts at render time. Declare every face.

Found later (A3, A4, A2):

* **A different local browser makes every project stale, so name the ids you render.** The manifest records the browser
  that rendered each MP4, and `render.mjs` re-renders a project whose browser differs. With no id it checks (and
  re-renders) every project; with ids it checks only those: with another Chromium, `render.mjs a03 --dry-run` listed only
  a03 while a bare `--dry-run` listed a02, a03 and a04. If a run did redo projects you did not author, restore them
  (`git checkout public/animations/<id>` and their old manifest entry) and commit only the ids you authored. Set
  `HYPERFRAMES_BROWSER_PATH` when `/opt/pw-browsers` is absent.
* `svgOrigin` is rejected by the validator, so rotate an HTML element whose centre is the pivot instead of an SVG group.
* The card class is `<prefix>-card` (copied with the prefix of the new animation), so a scene written for another
  prefix renders unstyled.
* A hand-computed value on screen was wrong once (the fraction of `0.1f` is 5033165; 4992205 was a mental slip), which
  is why the facts test must parse the scene text and compare with a real C run.
* **Bind variables with `data-var-text`, not `getVariables()`, inside a scene (A2).** A 1 s test render with
  `--variables-file` showed the file's value in a scene's `data-var-text` element, but `getVariables()` in that scene's
  script returned no value for a variable declared on the root `<html>`. `check` and `snapshot` get no
  `--variables-file`, so `a02-facts.test.ts` checks that each default and each bound element's text equal `variables.json`.
* **Vitest runs a `describe.skipIf` callback during collection even when the suite is skipped.** `collectFromProject()`
  there ran gcc, and a machine without gcc-13 failed collection (`spawnSync gcc-13 ENOENT`) instead of skipping.
  Put gcc work in `beforeAll`.
* **gcc 13 on another distro gives other numbers.** Debian 13's gcc 13.3 (glibc 2.41) printed 816 `.i` lines, 33 `.s`
  lines, a 1408-byte `hello.o` and a 15952-byte `hello`; an Ubuntu 24.04 userland gave 819, 50, 1544 and 15960. Run
  `node tools/anim/a02-facts.mjs --write` on Ubuntu 24.04 (CI, or the official `ubuntu-base` 24.04 tarball in a chroot
  with `gcc-13`), never on a look-alike. Re-running `--write` there leaves the committed `variables.json` unchanged.
* `hyperframes check` warns `connector_orphan` when an arrow's end is more than 32 px from every visible element
  (cards larger than 15% of the frame do not count) and a hidden element from another scene is that close. Start and
  end each arrow within a few pixels of the boxes it joins.

## Adding an animation

1. Copy `a01-press-run` to `aNN-topic`; rename the abbreviation, scene files, ids and the `__timelines` keys.
2. Write `animation.json`, then the scenes; give each scene `data-steps`, a rail entry, an `appearsBy` and a caption cue.
3. `node tools/anim/check.mjs --static aNN` while iterating, then `npm run anim:check`, then `npm run anim:render`.
4. Add a facts test if the animation shows values, and list the animation in `PLAN.md` section 8 and the lesson.
